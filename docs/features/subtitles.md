# Subtitles

How Stackarr discovers, searches, downloads and places subtitles. The provider seam is described
in [`contracts.md`](contracts.md).

## Model

`Stackarr.Subtitles` is the dispatcher and owns the whole workflow: shared settings, status,
search, candidate merging, downloads, notifications, automatic import coverage and the UI. It
asks every enabled provider for results and routes each download back to the provider that
supplied the candidate.

`Stackarr.Subtitles.Core` holds the implementation shared by the dispatcher and in-process
providers: library resolution, filesystem status and sidecar writing.

Two providers ship today:

- `Stackarr.Subtitles.OpenSubtitles` — in-process, enabled by default.
- `Stackarr.Bazarr` — optional container, disabled by default.

Adding a provider means adding an `ISubtitleProvider` implementation and a config section; it
does not need its own status logic, scheduler or UI.

```
movie / series / season / episode / player
                    |
          Stackarr.Subtitles (dispatcher + UI)
                    |
        ISubtitleProvider (all enabled)
          /                 \
OpenSubtitles          Bazarr
(in-process)           (container)
```

## Configuration

```yaml
services:
  subtitles:                 # shared dispatcher settings
    enabled: true
    languages: [en]
    autoDownload: true
    minScore: 70
    maxDownloadsPerRun: 10

    opensubtitles:           # built-in provider
      enabled: true
      apiKey: ""             # required
      username: ""           # optional; raises 5/day to 20/day
      password: ""
      includeMachineTranslated: false

    bazarr:                  # optional provider
      enabled: false
      proxy: false
      providers: [gestdown, subf2m]
```

The shared section controls languages, automatic downloads and the minimum score. Provider
sections only contain provider-specific settings. The UI hides itself when `services.subtitles`
is disabled or no provider is enabled/configured.

When more than one provider is enabled, search results from all of them are merged. The best
candidate wins; `provider` on the candidate determines which backend performs the download.

## Languages and status

`languages` is the ordered list downloaded automatically. Default: `[en]`. The list is normalised
to ISO 639-1, including the ISO 639-2/B codes some containers report (`fre` → `fr`, `ger` → `de`).

Status is provider-independent: sidecar files and embedded tracks are scanned once and compared
with the configured languages. Sidecars (`Movie.en.srt`, `Movie.fr.forced.srt`,
`Movie.de.hi.srt`, `.ass`, `.ssa`, `.vtt`) are read from the media folder; embedded tracks come
from ffprobe when the file is reachable and fall back to the arr's `mediaInfo.subtitles`.
Series and season status aggregate every episode with a file.

## OpenSubtitles

Search uses the OpenSubtitles.com REST API. Every request needs a user-supplied API key; a free
account raises the download quota from 5 to 20 per day. VIP accounts have higher limits.

- Movies search by IMDb id, TMDB id, title/year and the OpenSubtitles file hash.
- Episodes search by the series' IMDb/TMDB id plus season and episode, with the episode file
  hash and a `Series SxxExx` fallback query.
- Candidates are scored by hash match, release-name overlap with the video file, rating,
  download count, format and machine-translation flags.
- Downloads are requested as SRT, extracted from a ZIP when needed, normalised to UTF-8 where
  practical, and written atomically as a Jellyfin sidecar next to the video:
  `<video>.<lang>[.forced][.hi].srt`.

## Bazarr

Bazarr owns provider search, scoring and file placement through its own API. Stackarr keeps its
Sonarr/Radarr connections, language profile and provider list in sync.

`providers` defaults to the free `gestdown` and `subf2m`. Stackarr no longer configures the
`opensubtitlescom` provider inside Bazarr; OpenSubtitles is used directly through the built-in
provider. Other Bazarr providers can still be configured in Bazarr's own UI when proxied.

Bazarr's own wanted search is deliberately deferred: the shared dispatcher owns automatic
downloads, so the two systems cannot race on the same sidecar files. Bazarr still answers
specific search/download requests from the dispatcher.

Bazarr uses the LinuxServer image, a named config volume, `$tv:movies` and `$tv:shows`
read-write, and the stack network. Its API key is generated by Bazarr and read from
`/config/config/config.yaml` through Docker exec. Proxy is opt-in (`/bazarr`). The config job is
health-gated on both `bazarr` and `tv`.

## Automatic downloads

One shared job covers new imports. `MediaImportedEvent` carries the movie or episode ids; the
dispatcher asks every enabled provider for the missing languages, picks the best candidate and
downloads once. A six-hour catch-up job checks files added in the last week.

Older items are filled from the normal "Get missing" action or a manual search. The daily quota is
respected per provider; when a provider is exhausted the dispatcher logs it and continues with
the others. `maxDownloadsPerRun` bounds one sweep.

A successful download emits `media.tv.subtitle.downloaded` and `SubtitleDownloadedEvent`; the
latter triggers a Jellyfin library refresh.

## Requests, search and the player

One `SubtitleSearchDialog` is used by movie details, series details, the season bar, the episode
menu and the player subtitle menu. Search returns provider, language, score, release info,
forced/HI flags and a download action. Results are merged across providers and deduplicated by
provider + provider id. The movie and series actions belong to library detail views; remote media
popups and discovery cards never show a subtitle action.

The HTTP surface is authenticated: `GET /api/subtitles/languages`, `GET /api/subtitles/status`,
`POST /api/subtitles/search`, `POST /api/subtitles/download` and `POST /api/subtitles/request`.

The player publishes its Jellyfin item identity through `SubtitleSearchLauncher`; the shared
subtitle module resolves it to a Sonarr/Radarr target and opens the same popup. "Search
subtitles…" is offered only when a provider is enabled. A successful download renegotiates the
player at the current position and selects the language once indexed.

## Known limits

OpenSubtitles alone has a daily quota. Bazarr remains useful for multi-provider fallback and
non-English catalogues; enable both only if you want their results merged.
