Install first
The practical guide

Set up your stack,
properly.

Installing Arrk is the easy part. This guide walks through the choices that make a media stack pleasant to live with: where the files go, how quality is decided, what routes through the VPN, who gets in, and what happens when storage fills up.

About 30–45 minutes Config editor or YAML Safe defaults

Do this before you change anything

Back up /config (or at least arrk.yaml) and note your current ports. Arrk is early software and configuration can change between releases. The Config page keeps version history, but a real backup is still your friend.

Two ways to edit configuration

Open Configuration in Arrk for a validated visual editor with schema autocomplete and version history, or edit /config/arrk.yaml directly. Changes hot-reload without a restart. The generated JSON schema is the authoritative list of options; this guide covers the ones worth understanding.

01 Identity & admin

Arrk is the account authority for the stack. Start by replacing the bootstrap administrator and deciding how new accounts are created.

arrk.yaml 
auth:
  adminUsername: admin
  adminPassword: change-me-now
  sessionDays: 14
  requireHttps: false
  allowPasswordLogin: true
  allowLocalSignUp: true
  registrationMode: Approval   # Open | Approval | AdminOnly
  • Change the password after the first sign-in. The default is intentionally obvious.
  • Keep Approval for a household: new accounts wait for you.
  • Set requireHttps once the instance is only reachable over TLS.
  • Add Discord or MyAnimeList sign-in later from /account.
Good to know: Jellyfin and Navidrome keep their own credentials, but Arrk can provision accounts and passwords for them. That is separate from whether Arrk itself allows password login.

02 Storage & folders

Arrk uses three storage roots: configuration, downloads and media. Relative paths are anchored to the data root; absolute paths are passed directly to Docker. Get this right once and the rest of the setup is calmer.

arrk.yaml 
storage:
  config: /srv/arrk/config
  downloads: /srv/arrk/downloads
  media: /srv/arrk/media
  tv: $media/tv
  music: $media/music
PathUse it forAdvice
tvtv/movies and tv/shows underneath.Keep movies and shows on one filesystem for hard-links and fast imports.
musicThe native music library.Arrk writes Artist/Album/NN - Title with tags and cover art.
downloadsIncomplete, complete, Soulseek and staged uploads.Same filesystem as media is strongly preferred; imports can then link instead of copy.

Do not move folders after provisioning

Library managers remember root folders. If you must move storage, update the config and then re-point the libraries in the service UIs. Avoid mixing network shares with local disks for the download staging path.

03 Metadata

TMDb powers discovery, artwork and descriptions for movies and shows. A free API key or v4 read token is enough. Without it, Discover is limited and search falls back to what the library managers already know.

arrk.yaml 
metadata:
  tmdbApiKey: ""
  tmdbReadToken: ""
  • Prefer the v4 read token if you have one.
  • Keep the key out of screenshots and issue reports.
  • Music metadata comes from Deezer and does not need a key.

04 Quality profiles

Quality is defined once in Arrk and applied to the library managers. The default profiles are Best Available, FHD and UHD. Bitrate floors stop a “4K” release from being smaller than a good 1080p one.

arrk.yaml 
qualityProfiles:
  profiles:
    - name: Best Available
      minResolution: 1080p
      maxResolution: 2160p
      allowUpgrade: true
    - name: FHD
      minResolution: 1080p
      maxResolution: 1080p
      allowUpgrade: true
    - name: UHD
      minResolution: 2160p
      maxResolution: 2160p
      allowUpgrade: true
  minimumBitratesMbps:
    1080p: 3
    2160p: 12
One source of truth: the configured profiles are authoritative. Arrk creates and syncs them into the library managers rather than asking you to maintain copies in each app.
  • Set a tier to 0 to leave it unmanaged.
  • Use allowUpgrade deliberately; upgrades are extra download traffic.
  • Requests and uploads pick from these profiles.

05 Indexers

Prowlarr is the indexer hub and syncs its apps into the library managers. You can add indexers in Arrk's config or in Prowlarr's own UI (proxy it temporarily if you prefer). Keep credentials in the config, not in screenshots.

arrk.yaml 
indexers:
  proxy: false
  solver:
    enabled: false             # Byparr for Cloudflare-protected indexers
    tag: cf
  entries:
    - name: Example Torrents
      implementation: example
      enabled: true
      url: https://tracker.example
      categories: [2000, 5000]
      search:
        movieSearch: true
        tvSearch: true
        musicSearch: true
      settings:
        username: ""
        password: ""
  • Use the Cardigann definition name (for example 1337x, nyaasi) or a native implementation name.
  • Enable solver if a protected indexer needs a challenge solver; tag it cf.
  • Set indexers.proxy: true only while configuring; keep it private afterwards.
  • Test one search from Discover before adding a pile of indexers.

06 Downloads & VPN

Transmission handles torrents; slskd handles Soulseek for music. Both are provisioned by Arrk and appear on one Downloads page. The VPN is opt-in per service.

arrk.yaml 
vpn:
  enabled: false
  provider: protonvpn        # provider name understood by Gluetun
  type: wireguard
  wireguardPrivateKey: ""
  wireguardAddresses: ""
  serverCountries: ""
  portForwarding: false
  restart:
    enabled: true
    downloadThreshold: 5.0
    uploadThreshold: 5.0
    cooldownMinutes: 60

services:
  torrentDownloader:
    proxy: false
    vpn: true                # provisions the tunnel even with vpn.enabled false
    seeding:
      maxRatio: 2.0
      maxTimeMinutes: 1440
      minTimeMinutes: 30
    management:
      slow:
        enabled: true
        thresholdMbps: 1.0
        limitMinutes: 30
      stalled:
        enabled: true
        limitMinutes: 20
      storage:
        pauseDownloadsAtPercent: 90
        cleanupSeedingAtPercent: 85
        cleanupStrategy: oldest

The VPN is for the downloader, not everything

Routing is per service. Enabling the tunnel does not silently push your players or the whole stack through it.

  • Use a provider and credentials Gluetun understands.
  • With ProtonVPN/PIA port forwarding, enable portForwarding.
  • Leave slow/stalled cleanup on. It is speed-aware and holds off when the line is unhealthy.
  • Set monitoring.speedtest.minHealthyDownloadMbps to match your connection.

07 Players

Jellyfin plays video and can be fully managed by Arrk; Navidrome plays the music library. Both are proxied by default, and Arrk can sign users in with OIDC where the client supports it.

arrk.yaml 
services:
  jellyfin:
    enabled: true
    proxy: true
    nvidia: false             # true for NVENC / HDR tone mapping
    serverName: Arrk
    metadataLanguage: en
    metadataCountry: US
    manageUsers: true
    oidcSso: true
    webPlayer:
      enabled: true

  navidrome:
    enabled: true
    proxy: true
    webPlayer: true
  • Jellyfin libraries are created and kept linked automatically.
  • The in-site player keeps the Arrk look; disable it to use Jellyfin's own web client.
  • With NVIDIA enabled, pass the GPU to the Jellyfin container and let Arrk configure transcoding.
  • Keep Navidrome's webPlayer on unless you only want external Subsonic clients.

08 Subtitles

One dispatcher covers every subtitle request. OpenSubtitles works in-process and is enabled by default; Bazarr is optional and useful when you want more providers or non-English catalogues.

arrk.yaml 
services:
  subtitles:
    enabled: true
    languages: [en]
    autoDownload: true
    minScore: 70
    maxDownloadsPerRun: 10
    opensubtitles:
      enabled: true
      apiKey: ""
      username: ""            # optional; raises the free quota
      password: ""
      includeMachineTranslated: false
    bazarr:
      enabled: false
      providers: [gestdown, subf2m]
  • Register a free OpenSubtitles API key under Profile → API Consumers.
  • Add your languages in priority order; the first is the default.
  • New imports are covered automatically; older items use “Get missing” or a manual search.
  • Keep Bazarr's own wanted search out of the way; the shared dispatcher owns automatic downloads.

09 Remote access

Traefik runs the reverse proxy. Path-based routes are on by default, the Arrk UI is at /, and players are proxied at /jellyfin and /navidrome. A Cloudflare tunnel can expose Traefik without opening host ports.

arrk.yaml 
routes:
  baseUrl: http://localhost
  publicUrl: https://media.example.com
  proxy: true
  httpPort: 80
  httpsPort: 443
  cloudflared:
    enabled: false           # enable after adding a tunnel token
    tunnelToken: ""
  • Set publicUrl to the exact external URL; it is used for deep links and OIDC.
  • For a tunnel-only host, set both ports to 0.
  • Enable auth.requireHttps when TLS terminates in front of Arrk.
  • TLS certificate automation is not there yet; use your proxy or tunnel for HTTPS.
Several stacks, one host: give each instance a unique StackName and non-overlapping host ports. Each gets its own stackarr-<name>-net network, so identical service names never collide.

10 Users & requests

Decide who can sign in and what they can do. Arrk supports admin/user roles, invite-only approval, OIDC for players, and a Seerr-style request flow for people who should not add media directly.

arrk.yaml 
auth:
  registrationMode: Approval
  provider:
    enabled: true
    issuer: ""                # defaults to routes.publicUrl
  external:
    discord:
      enabled: false
      clientId: ""
      clientSecret: ""
      callbackPath: /signin-discord
  players:
    provisionAccounts: true
    provisionPasswords: true

requests:
  enabled: true
  allowSeriesRequests: true
  allowSeasonRequests: true
  allowEpisodeRequests: true
  maxOpenPerUser: 0
  blacklistOnDeny: false
  autoApproveRoles: [Admin]
  • Register the Discord redirect URI in the Discord developer portal if you enable it.
  • Pending accounts cannot sign in until an admin approves them.
  • Keep maxOpenPerUser at 0 only if you trust the household.
  • Requests are moderated at /requests; admins can add media directly.

11 Notifications

Arrk records every notable event, shows it in the in-app inbox and can deliver a subset to Discord or a generic webhook. Routing is per topic, so TV noise and system failures can go to different places.

arrk.yaml 
notifications:
  retentionDays: 90
  showJobActivity: false
  discord:
    enabled: true
    webhookUrl: "https://discord.com/api/webhooks/..."
    username: Arrk
    routing:
      media.#: "https://discord.com/api/webhooks/.../media"
      system.#: "https://discord.com/api/webhooks/.../system"
    exclude:
      - downloads.progress
  webhook:
    enabled: false
    url: ""
    authHeader: ""
  topics:
    downloads.progress: false
    system.health: true
  • Start with one Discord webhook and the default topic set.
  • Use exclude to silence a channel without hiding the event in-app.
  • Turn on showJobActivity only when debugging scheduled jobs.

12 Lifecycle

Watch history drives staleness. The defaults are conservative: warn after a period, give bookmarked items longer, and never delete automatically unless you explicitly enable it.

arrk.yaml 
monitoring:
  tv:
    stale:
      upperThreshold: 30       # days without consumption
      lowerThreshold: 0        # early warning; 0 disables
      autoCleanup: false       # opt in deliberately
      keepThreshold: 45        # bookmarked titles
      keepLowerThreshold: 0
  music:
    stale:
      upperThreshold: 30
      lowerThreshold: 0
      autoCleanup: false
      keepThreshold: 45
      keepLowerThreshold: 0
  • TV staleness is per season; movies and music albums are single items.
  • Consuming an item — or anything in its season/album — resets the clock.
  • Pin anything an admin never wants considered stale.
  • Review /stale for a while before enabling automatic cleanup.

13 Optional AI

AI is off by default, provider-agnostic and advisory. Every feature has its own toggle and falls back to the deterministic path. Bring any OpenAI-compatible endpoint, including a local model.

arrk.yaml 
ai:
  enabled: false
  provider: gemini            # or openai, ollama, custom, ...
  apiKey: ""
  baseUrl: ""                 # set for a custom OpenAI-compatible host
  models:
    chat: gemini-3.6-flash
    fast: gemini-3.5-flash-lite
  features:
    assistant:
      enabled: true
      maxMessagesPerHour: 30
    releaseRanking:
      enabled: true
      mode: shadow             # off | shadow | ambiguous | always
    importMatching:
      enabled: true
      mode: ambiguous
    style:
      enabled: true
  privacy:
    storePromptText: false
  • Start in shadow mode to compare choices without changing behaviour.
  • Destructive actions require explicit confirmation and run through the same services as the UI.
  • Leave prompt storage off unless you are actively debugging.
  • Check /ai for usage, spend and feature health.

14 Day two

A stack is a living thing. The boring maintenance habits are what keep it pleasant.

Updates

Pull a new image, keep the same mounts and StackName, and re-create the container. Back up /config first. Arrk can check image updates, but you decide when to apply them.

Backups

/config holds the YAML, both SQLite databases, service config volumes and encryption keys. Treat it as the crown jewels. A nightly copy to another disk is enough for most homes.

Config history

The Config page keeps versions of arrk.yaml. When something feels off, compare against the previous version before hand-editing. Keep a copy outside the container too.

When something breaks

Start with docker logs -f arrk, then /events for the event trail and /logs for the app log. The service's own UI is still there when you need the deeper view.

A sane default posture

Approval-only accounts, no automatic deletion, slow/stalled cleanup on, VPN on the downloader only, and a weekly config backup. Change one thing at a time.

Open Discover, pick a title, and watch the whole loop work. If something is confusing, the FAQ and the source docs are the next stop.
