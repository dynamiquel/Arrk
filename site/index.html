Why Stackarr

The stack should feel like one product.

A great self-hosted media setup is usually a dozen containers, a dozen logins and a config you are afraid to touch. Stackarr keeps the services that do the work and smooths over the seams between them.

The usual evening
  • Five tabs just to find out whether a download finished.
  • Different logins for every app, and another one for the family.
  • Quality profiles and indexers configured in three places.
  • A stalled torrent sits there for days, quietly wasting space.
  • Cleanup is a manual job you never quite get around to.
With Stackarr
  • One dashboard for discovery, requests, playback and downloads.
  • One account for the whole household, with OIDC for players.
  • One config defines quality, indexers and download clients.
  • Slow, stalled and failed downloads clean themselves up.
  • Watch history drives watchlists, warnings and optional cleanup.

What you get

Everything in one place, without flattening everything.

Stackarr does not replace the tools that do the heavy lifting. It provisions them, configures them through their APIs and gives you a single, friendly surface on top.

A dashboard that knows your stack

Continue watching, storage, service health, downloads and recent additions in one place. Arrange the tiles the way you think, with per-account layouts and text sizes.

  • Module-contributed tiles and a visual tile editor
  • Live status for services, storage and the network

Movies & shows, without the maze

Discover, request, add and upgrade films and series through one catalogue. Quality profiles, indexers and missing-content searches are handled for you.

  • Trending, popular, upcoming and seasonal anime
  • Failed-download recovery and retries

A music library that feels native

Stackarr owns the music library itself. Deezer provides identity and metadata; torrents and Soulseek bring the files; Navidrome plays them.

  • Albums, artists, playlists and synced lyrics
  • Identify-first imports with real tags and cover art

Downloads that clean up after themselves

Transmission and slskd share one downloads page. Seeding goals, storage limits and slow, stalled or errored torrents are monitored — and cleaned up without nuking a degraded connection.

  • Speed-aware slow/stalled detection with recovery
  • Optional VPN routing for downloads and Soulseek

People, requests and permissions

Invite the household. Give everyone their own watch history and watchlists, let them request media, and keep the admin controls with the admins.

  • Invite-only accounts with approval and roles
  • OIDC, Discord and MyAnimeList sign-in

A stack that looks after itself

Watch history becomes a lifecycle. Bookmark something to keep it longer, pin it to keep it forever, or let Stackarr suggest what to reclaim when storage gets tight.

  • Stale warnings, reclaimable-space view and pins
  • Automatic deletion is opt-in, never a surprise
From request to ready

The quiet work happens in the background.

Built to be extended

Modular underneath. Approachable on top.

Every service is a self-contained module. Built-in features and drop-in plugins use the same contracts for navigation, pages, jobs, endpoints and dashboard tiles.

  • One module per concern, loaded at startup
  • Plugins can contribute full pages and UI regions
  • The shell never references a feature module directly
See how it fits together
MyModule.cs 
public sealed class MyModule : IStackarrModule
{
    public string ModuleName => "MyPlugin";

    public IReadOnlyList<Service> GetServices() => [];

    public void ConfigureServices(
        IServiceCollection services,
        IConfiguration configuration)
    {
        services.AddSingleton<INavigationProvider, MyNavigation>();
        services.AddSingleton<IHeadAssetProvider, MyHeadAssets>();
    }
}

A personal project, shared early

Stackarr started as one person's answer to the headaches of stitching together self-hosted media tools. It is still an early, actively changing project: features move, configuration evolves and rough edges exist. Treat it as a labour of love, not a commercial product — read the docs, back up your config, and expect the occasional change. More about the project.
