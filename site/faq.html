What Arrk is, what it is not, what it needs, and what to expect while it is still early. If something is missing, the source docs and GitHub issues are the next stop.

Project & philosophy

What is Arrk?

Arrk is one web UI and one config for a self-hosted media stack. It provisions and configures the services around your library — movies, shows, music, downloads, subtitles, players — and gives you a single place to discover, request, watch, listen and clean up.

It does not replace those services. They still do the heavy lifting. Arrk orchestrates them, talks to their APIs and smooths over the seams between them.

Is this stable enough to use?

It is an early alpha, and it is a personal project. The core loop is used daily, but features move, configuration keys evolve and rough edges exist. Treat it as a labour of love rather than a commercial product: back up /config, read release notes, and change one thing at a time.

If you need a frozen, support-backed platform, wait. If you enjoy shaping a stack with the person building it, you are in the right place.

Why does Arrk exist?

Because a self-hosted media setup should not feel like a second job. The usual stack solves each individual problem well, but the whole experience is a dozen tabs, a dozen logins and configuration that drifts. Arrk started as one person's answer to those headaches.

Is it open source?

Yes — MIT licensed. You can read it, run it, modify it and build on it. Issues and pull requests are welcome, though there is no support contract or response-time promise. The project is shared because it might be useful, not because it is finished.

Does it phone home?

There is no telemetry or analytics built in. Arrk talks to the services and metadata providers you configure — for example TMDb, Deezer, OpenSubtitles, Discord, MyAnimeList, indexers and your chosen AI provider. If you use a local AI endpoint, even that traffic stays on your network.

What does it run on?

A Linux host with Docker. Arrk needs the Docker socket to create sibling containers and uses three host folders for config, downloads and media. Docker Desktop on macOS or Windows is not a supported host; the container expects a real Linux Docker daemon.

Can I run more than one instance?

Yes. Give each instance a unique StackName. Containers become stackarr-<name>-* and each gets its own stackarr-<name>-net network, so identical service names do not collide. Give them separate storage roots and non-overlapping host ports.

Setup & services

Do I need all the supported services?

No. Modules can be disabled and their UI hides live. A sensible small setup can start with movies/shows and downloads, add Jellyfin later, and leave music, subtitles, MyAnimeList and AI off until you want them. Some infrastructure — the reverse proxy, for example — is core to how Arrk exposes things.

Can I keep my existing media library?

Your media folders are just folders: point the storage mounts at them and let the library managers see the right paths. What Arrk does not do yet is adopt an existing stack's service configurations wholesale — it expects to provision and own the containers it manages. Migrate in stages and keep a backup of the old setup.

Do I need a domain or Cloudflare?

No. Arrk works on a LAN with a published port. Traefik is there for path-based routing, and a Cloudflare tunnel is optional for remote access without opening host ports. Set routes.publicUrl to whatever URL you actually use.

Does it handle HTTPS certificates?

Not automatically yet. Traefik routing and middleware exist, but certificate provisioning is still a gap. Put Arrk behind a TLS-terminating proxy or tunnel, and enable auth.requireHttps once it is served over HTTPS.

Do I need a TMDb key?

Strongly recommended. TMDb powers discovery, artwork and descriptions. Without it, Discover is limited and search falls back to what the library managers already know. A free API key or v4 read token is enough.

Can I use qBittorrent, SABnzbd or Plex?

The built-in paths are Transmission for torrents, slskd for Soulseek, and Jellyfin for video playback. There is no Usenet client and no Plex integration today. Because the service layer is modular, alternative implementations could be added later — but treat that as a code contribution, not a config option.

Does it replace Jellyfin or the *arr apps?

No. Jellyfin still produces the video stream; Radarr and Sonarr still own the movie and show libraries; Prowlarr still owns indexers. Arrk provisions them, configures them through their APIs and puts a single UI in front. Their own UIs stay reachable for advanced work.

Features

How does the music stack work?

Arrk owns the library itself: artists, albums, tracks, playlists and acquisition. Deezer supplies identity and metadata. Torrents and Soulseek bring the files. Releases are identified before they are placed, so tags, artwork and folder names match. Navidrome plays the result, both in-site and through Subsonic clients.

Is the AI required?

No. It is off by default, opt-in per feature and provider-agnostic. The assistant, release ranking and import matching all keep a deterministic fallback. Destructive actions require explicit confirmation and run through the same services as the UI.

What about anime?

Sonarr handles anime libraries, and the MyAnimeList module can link or sign in with MAL, browse and edit your list, map MAL cours to local seasons, and sync completed episodes and scores. Plan to Watch appears as a watchlist.

Can users request media without admin access?

Yes. The request system supports movies, series, seasons, episodes, artists, albums and tracks. Admins moderate, optionally blacklist on denial, and can auto-approve specific users or roles. Requests go through the owning library module rather than talking to Radarr, Sonarr or Deezer directly.

Does it clean up old media automatically?

Only if you enable it. Watch history drives staleness, but the defaults warn rather than delete. Admins can review reclaimable space, pin anything that must never go stale, and turn on automatic cleanup per media type when they are comfortable.

What notifications are supported?

A durable event log, an in-app inbox and feed, Discord delivery and generic JSON webhooks. Routing is per category, and each channel can exclude topics without hiding them from the in-app feed. More channels can be added through the notification channel contract.

Privacy & safety

Is mounting the Docker socket safe?

It is powerful. Anyone who controls the Arrk container can control the Docker daemon, which is effectively root on the host. Run Arrk on a dedicated media host, keep the UI behind authentication and HTTPS, and do not expose the Docker socket or the Arrk container to untrusted users.

Can I expose Arrk to the internet?

You can, but only the sign-in surface is meant to be public. Put it behind HTTPS, keep registration on approval or admin-only, use strong admin credentials, and consider a VPN or tunnel rather than opening raw ports. The reverse proxy and tunnel exist for this; use them deliberately.

How are accounts managed?

Arrk is the account authority and can act as an OpenID Connect provider for players. Registration can be open, approval-based or admin-only. Discord and MyAnimeList can federate in. Jellyfin and Navidrome keep their own credentials, which Arrk can provision for clients without OIDC.

What does the AI provider see?

Only what a feature sends to the model you configure. Library state comes from tools, not the model's imagination, and prompt text is not stored by default. If that matters to you, point ai.baseUrl at a local OpenAI-compatible server and keep everything on your network.

If something goes wrong

Where do I look first?

Start with docker logs -f arrk, then the in-app /events feed and /logs. The service's own UI is still available for a deeper view. Most first-run issues are permissions, ports or a public URL that does not match the browser.

Why do ports 80 or 443 conflict?

Traefik publishes them by default. Change routes.httpPort and routes.httpsPort, or set both to 0 for a tunnel-only deployment. The direct Arrk port is 5186.

Why does sign-in loop or redirect to the wrong host?

Set routes.publicUrl to the exact URL in your browser, including the scheme. If TLS terminates in front of Arrk, enable auth.requireHttps and make sure forwarded headers are trusted from your proxy network. Changing the public URL can invalidate cookies; sign in again.

How do I update safely?

Back up /config, pull the new image, then re-create the container with the same mounts and StackName. Watch the first boot logs. If a config key changed, the validator will tell you; use the Config page's version history to compare.

Where can I ask for help?

Open an issue on GitHub with the relevant logs, your Arrk version, host setup and what you expected to happen. Please remove API keys, passwords and personal paths before posting. There is no guaranteed response time, but clear reports are genuinely appreciated.
