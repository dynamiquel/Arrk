Quick start
Setup in one container

From zero to a
working stack.

Stackarr runs on a Linux host with Docker. You give it three host folders and access to the Docker socket; it creates the network, provisions the services and configures them through their APIs.

Before you begin

What you need.

A small always-on machine is plenty. The services do the heavy lifting; Stackarr is a single ASP.NET Core app that orchestrates them.

Linux + Docker Docker Engine and the Compose plugin. The host's Docker daemon is used to create sibling containers.
Docker socket Access to /var/run/docker.sock. This is powerful — treat the Stackarr container as root-equivalent.
Three directories Configuration, downloads and media. Use a disk with room for the library you expect to build.
Network access Outbound internet for image pulls, metadata, indexers and players. Inbound is optional.

Use a host you control

Mounting the Docker socket lets Stackarr create and remove containers. Run it on a dedicated media host, not on a machine shared with things you do not want it to touch. Back up /config before upgrades.

What Stackarr actually runs

One container in front. The rest behind it.

You start stackarr. It provisions the reverse proxy, the services you enable, the download clients and the VPN sidecar when needed. Their own UIs stay reachable for advanced work.

StackarrYour one web UI and config
Traefik + optional Cloudflare tunnelReverse proxy and remote access
Library, downloads, playersMovies, shows, music, torrents, Soulseek, Jellyfin, Navidrome
VPN sidecar when askedGluetun for routed download traffic
Quick start

Three ways in. Pick one.

All three end up with the same container, mounts and StackName. The launcher is the friendliest; Compose is the most declarative.

1

Get the project

Clone the repository if you want to use the launcher or Compose. The plain docker run below needs only Docker.

shell 
git clone https://github.com/dynamiquel/Stackarr.git
cd Stackarr
2

Recommended: use the launcher

The script creates the storage directories and Docker network, pulls ghcr.io/dynamiquel/stackarr:latest, then starts Stackarr. It defaults to ./stackarr-data/{config,downloads,media} and publishes the UI on :5186.

shell 
./scripts/run-stackarr.sh

Point it at existing storage or choose another port:

shell 
./scripts/run-stackarr.sh \
  --data-root /srv/stackarr \
  --name stackarr \
  --stack-name media \
  --host-port 8080

Pass --no-port for a tunnel-only instance that publishes no host ports.

3

Or: Docker Compose

The Compose file describes only the Stackarr container; Stackarr handles the rest. It pulls the published image, writes data under ./stackarr-data by default and is tunnel-only unless you publish a port.

shell 
docker compose up -d

A small .env makes the deployment easier to read:

.env 
STACKARR_STACK_NAME=media
STACKARR_CONTAINER_NAME=stackarr-media
STACKARR_CONFIG_DIR=/srv/stackarr/config
STACKARR_DOWNLOADS_DIR=/srv/stackarr/downloads
STACKARR_MEDIA_DIR=/srv/stackarr/media

# Uncomment to publish the UI on the host:
# STACKARR_HOST_PORT=5186
4

Or: plain docker run

Create the network and directories first, then pull the published image and run the container.

shell 
mkdir -p /srv/stackarr/{config,downloads,media}
docker network create stackarr-media-net
docker pull ghcr.io/dynamiquel/stackarr:latest

docker run -d \
  --name stackarr \
  --network stackarr-media-net \
  --restart unless-stopped \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v /srv/stackarr/config:/config \
  -v /srv/stackarr/downloads:/downloads \
  -v /srv/stackarr/media:/media \
  -p 5186:5186 \
  -e StackName=media \
  ghcr.io/dynamiquel/stackarr:latest

StackName namespaces every container Stackarr creates (stackarr-media-*) and its Docker network (stackarr-media-net), so multiple stacks can share a host.

First boot

What happens next.

First boot pulls images, creates the network and provisions each enabled service. It can take a few minutes. Follow along with docker logs -f stackarr.

Config is created/config/stackarr.yaml is generated with defaults and a placeholder admin account.
Services are provisionedTraefik first, then Gluetun if needed, then every enabled service in dependency order.
APIs are configuredRoot folders, quality profiles, indexers, download clients, libraries, users and the player theme.
You sign inThe UI is at :5186, through Traefik at /, and at /jellyfin and /navidrome.
Your first login

Change the placeholder password.

The generated config creates an administrator from auth.adminUsername and auth.adminPassword, defaulting to admin / admin. Sign in, open your account, and change it before anyone else can reach the instance.

stackarr.yaml 
auth:
  adminUsername: admin
  adminPassword: change-me-now
  • Change the admin password immediately.
  • Set routes.publicUrl if the instance is reachable from outside.
  • Enable auth.requireHttps once TLS is in front of it.
  • Back up /config before you start shaping things.
Storage

Three mounts. That is the whole contract.

Relative storage paths are anchored to Stackarr's data root; absolute paths are used verbatim as Docker bind sources.

Host pathContainerWhat lives there
/srv/stackarr/config/configstackarr.yaml, Stackarr and Hangfire SQLite databases, service config volumes, OIDC and Data Protection keys.
/srv/stackarr/downloads/downloadsIncomplete and complete torrents, Soulseek transfers, staged uploads and import scratch space.
/srv/stackarr/media/mediaYour library: tv/movies, tv/shows and music by default.

Prefer existing storage? Point the mounts at it instead. Keep downloads and media on the same filesystem when possible so imports can hard-link rather than copy.

Ports & remote access

Direct, proxied or tunnel-only.

Stackarr listens on 5186 for bootstrap access. Traefik publishes host 80 and 443 by default. If those ports are taken, or you do not want any inbound ports, change them in config.

stackarr.yaml 
routes:
  baseUrl: http://localhost
  publicUrl: https://media.example.com
  httpPort: 80       # 0 = do not publish
  httpsPort: 443     # 0 = do not publish
  cloudflared:
    enabled: false           # enable after adding a tunnel token
    tunnelToken: ""
Common shapes
Direct on the LANPublish 5186. Simplest for a first run.
Reverse proxiedTraefik on 80/443, services under path routes.
Tunnel-onlySet both ports to 0; Cloudflare exposes Traefik.
Several stacks, one hostGive each a unique StackName and non-overlapping ports.

TLS certificates are not automated yet. Put Stackarr behind a TLS-terminating proxy or tunnel and set auth.requireHttps.

Troubleshooting

When the first boot is not boring.

Most setup problems are about permissions, ports or a stale public URL. These are the usual suspects.

“Cannot talk to the Docker daemon”

Stackarr needs the host Docker socket. Check that it is mounted and that the container can reach it:

shell
docker exec stackarr ls -l /var/run/docker.sock
docker exec stackarr docker info

On SELinux hosts, the socket mount may need a label. Stackarr is designed for Linux; Docker Desktop on macOS/Windows is not a supported host.

Ports 80 or 443 are already in use

Either stop the other service, change the Traefik ports in config, or disable host publishing entirely for a tunnel-only deployment:

stackarr.yaml
routes:
  httpPort: 8080
  httpsPort: 8443
First boot seems stuck

Pulling service images is the slow part. Watch the log rather than assuming it has failed:

shell
docker logs -f stackarr
docker ps --filter name=stackarr-

A slow first pull is normal. A loop of failed starts usually points at a port conflict or a missing storage directory.

Sign-in loops or redirects to the wrong host

Set routes.publicUrl to the exact URL you use in the browser, including scheme. If TLS terminates in front of Stackarr, set auth.requireHttps and make sure forwarded headers are allowed from your proxy network. Changing the public URL invalidates some cookies; sign in again.

Media imports but players do not see it

Confirm the library mounts point at the same host folders and that Jellyfin libraries use the paths inside its container (/movies, /shows, /music). Stackarr triggers a scan after imports, but a manual refresh can help while you are setting up.

Permission errors under /config

The mounted config directory is often root-owned. Back it up first, then inspect or edit from inside the container:

shell
docker cp stackarr:/config/stackarr.yaml ./stackarr.yaml.bak
docker exec -it stackarr sh -c 'vi /config/stackarr.yaml'
